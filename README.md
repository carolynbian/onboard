# 初见 Onboard（演示版）

企业员工服务 AI 助手。当前进度：能在本机打开、创建工作空间、登录、权限控制、组织架构、员工管理。

## 怎么打开

1. 打开 `onboard` 文件夹；
2. 双击 `index.html`，用电脑自带的 Edge 或 Chrome 浏览器打开。

不需要安装任何软件，也不需要联网。

## 第一次打开

页面会显示“创建你的工作空间”：

- 管理员姓名：你希望在公司里显示的名字；
- 登录账号：至少 4 位，不能有空格；
- 密码：至少 10 位。

点“创建并进入”后会自动登录，直接进入主界面。

## 登录页

- 左边是品牌区：主标语“从第一天起，让每个问题都有据可依。”和副标语；
- 右边是登录卡片，有两个标签：“员工登录”（用员工编号 / 员工账号）和“管理后台”（用管理账号）；
- 密码框右侧有“显示密码”勾选；
- “忘记密码？”只会提示联系公司 HR 或系统管理员重置密码；
- 页面底部注明“账号由公司管理员分配，无公开注册”，没有注册入口。

## 角色与权限

系统内有四种角色（每个账号都有姓名、账号、部门、角色、是否启用）：

| 角色 | 说明 | 现在能看到 |
| --- | --- | --- |
| 员工 | 普通员工 | 工作概览、员工服务助手、我的年假、工单与入职、制度中心、组织架构 |
| HR 管理员 | 管员工、制度、年假、工单 | 工作概览、员工服务助手、我的年假、工单与入职、制度中心、组织架构、员工管理、年假管理、员工问询、服务管理、制度知识库（只能管“员工”角色的账号） |
| 产品运营 | 观察回答质量并优化 | 工作概览、员工服务助手、我的年假、工单与入职、制度中心、组织架构 |
| 系统管理员 | 拥有全部权限 | 工作概览、员工服务助手、我的年假、工单与入职、制度中心、组织架构、员工管理、年假管理、员工问询、服务管理、制度知识库、模型配置（可以分配和编辑所有角色） |

- 创建工作空间时，创建者自动成为**系统管理员**；旧版本数据里的“管理员”会自动升级成“系统管理员”。
- 侧栏底部显示当前用户的部门 + 角色中文名。
- 权限判断在**代码内部**执行：每个页面进门前都会检查当前角色有没有对应权限，没有就直接拒绝并显示“无权访问”，不是只把按钮藏起来；手动改地址也不行。
- 被停用的账号不能登录（提示“该账号已停用，请联系公司管理员。”）；如果登录状态还在但账号被停用，刷新后也会被退出。

## 组织架构

- 以公司为顶层，下面按部门分组，展示每个部门里**启用状态**的成员（头像字 + 姓名）；停用的账号不显示。
- 现有数据里没有上下级汇报关系，所以这一页只做“部门—成员”的目录：不画汇报线，也不显示或编造职位。
- 所有角色都能看这一页；只有管理员（HR 管理员、系统管理员）会多出两个按钮：
  - “新增部门”：填写部门名称即可，新部门会出现在组织架构和员工管理的部门下拉里；
  - “员工管理”：直接跳到员工管理页面。

## 员工管理

系统管理员、HR 管理员登录后，左侧菜单的“管理后台”分组里会出现“员工管理”：

- 表格列：员工（头像字 + 姓名）、员工编号、部门、角色、状态、操作。
- 右上角“新增员工”：填写姓名、员工编号、部门、角色、初始密码（至少 10 位）。员工编号同时是登录账号，创建后不能修改。
- 部门下拉里预置了五个**示例**部门：产品部、技术部、销售部、财务部、人力资源部；选“＋ 输入新部门…”可以填一个新部门。
- 每行“编辑”：可改姓名、部门、启用/停用，也可以重置密码（留空表示不改）；员工编号和角色不能改。
- 右上角“批量导入”：
  - 先下载模板（CSV，Excel / WPS 可直接打开），列是：姓名、员工编号、部门、角色；
  - 上传后只做“预览与校验”，每一行显示通过或不通过，并写明原因（编号重复、部门为空、角色不合法、没有该角色的导入权限等）；
  - 点“确认导入”才真正写入；有问题的行自动跳过，导入完会显示“导入了几行、跳过了几行”；
  - 导入需要填一个“统一初始密码”（至少 10 位），所有导入账号用它登录。
- 权限规则（在代码内部再查一次，改页面也绕过不了）：
  - HR 管理员新增账号时只能选“员工”角色；系统管理员可以新增 HR 管理员、产品运营、系统管理员。
  - HR 管理员只能编辑“员工”角色的账号。
  - 不能编辑当前登录的账号（避免把自己停用）。

## 小初 · 员工服务助手（独立入口）

- 独立页面：`onboard/assistant/index.html`。静态部署到站点根目录时地址是 `/assistant/`；本地直接双击 `onboard\assistant\index.html` 打开。
- 布局：顶部品牌栏（品牌名、“员工服务中心”标签、“产品学习 / 工作台”链接、当前用户头像姓名、退出）；左侧虚拟形象区；右侧聊天区。
- 虚拟形象“小初”：纯矢量 SVG 的圆润机器人（浅蓝外壳、深蓝屏幕脸、青色发光眼睛和微笑），带上下浮动动画；提问和等待回答时进入“思考中”状态（眼睛和表情变化）。不是真人数字人，也没有语音。
- 形象下方快捷入口：我的年假、报销怎么办、新人入职指南、请假与考勤、查看工单（前四个直接发送问题，最后一个跳到主站工单页）。
- 聊天区标题“和小初聊聊”、副标题“公司制度 · 入职指引 · 员工服务”，右侧“历史咨询”下拉和“新咨询”按钮。
- 欢迎语按当前员工显示姓名；回答上方显示小初小图标、署名“小初”和“基于公司已发布制度与个人记录”。
- **聊天功能与主站“员工服务助手”完全共用**：同一个 app.js、同一套本地数据和同一套发送/回答/核验/反馈/转人工逻辑，两边共用“最近咨询”历史，数据互通。
- 手机宽度下虚拟形象缩小、聊天区变单列，快捷入口横向滚动。

## 员工服务助手（员工端）

所有角色登录后，左侧“员工服务”里的“员工服务助手”是聊天界面。

- 第一次进入：欢迎区“工作中的疑问，从这里开始。”，三张快捷卡片（了解公司制度、查查我的年假、找到办事方法）和两个示例问题（“年假可以结转到明年吗？”“试用期有哪些规定？”），点一下就直接发送。
- 输入框提示“输入你的问题，例如：我还有几天年假？”；回车发送，Shift+回车换行，输入法选字时的回车不会误发送；最多 2000 字。
- 发送按钮是向上箭头，等待回答时变成转圈。
- 输入框下方两行提示：回答前核对制度与数据；制度解释附原文依据；个人信息仅查询本人记录。依据不足时会明确说明。
- 左侧“开始新咨询”下面列出“最近咨询”（最多 12 条，标题取第一个问题），点击可恢复整段对话。
- 对话记录只属于提问的员工本人：`store.listMyChatSessions / getMyChatSession / appendChatMessage` 都按当前登录用户校验，即使页面上的会话 ID 被改，也看不到别人的咨询。
- 目前回答是固定占位回复；下一步接入真正的制度问答。

## 我的年假（员工端）

所有角色登录后，左侧“员工服务”里都有“我的年假”，用来查看自己的年假。

- 表格列：年度、剩余年假（天）、最后更新时间、变更记录（“查看 N 条流水”）。
- 只显示本人各年度的记录，点开流水可以看到每一笔的原因、增减天数和时间。
- **只能看自己**：这条限制在数据层实现（`store.canViewUserLeave / listLeaveEntriesFor / getLeaveBalanceFor`）。页面上的按钮参数即使被人改成别人的员工 ID，也会被内部检查拒绝，不会显示别人的记录。
- 本人没有任何记录时显示空状态：“请联系 HR 录入你的年假数据；没有记录不代表余额为零”。
- 页面底部提示：余额由 HR 维护。

## 年假管理（HR 管理后台）

左侧“管理后台 → 年假管理”，只有 HR 管理员和系统管理员能进入。

- 表格列：员工（姓名 + 账号）、年度、剩余年假（天）、最后更新时间、变更记录（“查看 N 条流水”）。
- 右上角“调整年假”：选择员工、年度、增加或减少的天数，以及调整原因（必填）。每次调整生成一条流水；**余额 = 全部流水合计**（不单独存余额字段），历史流水不能删除。
- 右上角“导入余额”：下载 CSV 模板（员工账号、年度、余额（天）），上传后先预览校验，确认后才写入；与现有余额不一致时会生成一条“对账调整”流水，而不是覆盖历史。
- 非数字、空值、0 天、超过 365 天都会给出中文提示；允许负数（表示减少），余额为负会标红。
- 页脚提示：余额由 HR 维护；导入余额会生成对账调整流水，历史变动始终保留。

## 制度知识库（HR 管理后台）

左侧“管理后台 → 制度知识库”，只有 HR 管理员和系统管理员能进入。

- 右上角“上传制度”：支持 PDF、Word（.doc / .docx）、文本（.txt）；填写制度名称、分类（公司制度 / 入职指南 / 报销制度 / 请假制度 / 部门制度 / 福利保障）、适用范围（全员或某个部门）、版本号、生效日期。
- 上传后状态自动流转：**排队中 → 解析中 → 待发布**；解析失败会显示原因，并提供“重试”。解析在后台进行，页面每 2 秒左右自动刷新状态。
- 点“查看详情”可以预览解析出来的文字（含表格行），确认没有乱码、表格没丢之后再手动“发布”；已发布的可以“下架”，已下架的可以重新发布。
- 页面上方有状态标签（全部、已发布、待发布、失败、已下架）、分类筛选、适用部门筛选和按名称搜索。
- 页脚提示：只有已发布、在有效期内、适用员工部门的制度才会用于回答；扫描件 PDF 需要先做文字识别。
- 原始文件保存在本机（演示版单个文件请小于 1.5MB），下载按钮会在代码里检查登录状态和“制度管理”权限，不提供可直接访问的文件地址。

说明：这是纯本机演示版本，**PDF / Word 的“解析”是模拟流程**（txt 会读取真实内容，PDF/Word 显示标注为演示的示例正文）；状态流转、预览、发布/下架、权限检查和受控下载都是真实逻辑，接入后端解析服务后可替换为真实提取结果。

## 制度中心（员工端）

所有角色登录后，左侧“员工服务”里都有“制度中心”。

- 顶部横幅：“每一项制度，都有清晰的依据”；下方显示当前部门，并说明“可查看全员及本部门的有效制度”。
- 卡片列表：文件图标、适用范围标签（全员可见 / 某部门专属）、分类、制度名称、版本与生效日期、“查看制度正文”。
- 上方有分类下拉筛选和名称搜索；没有结果时给出友好的空状态说明。
- 只展示：已发布 + 在有效期内 + 适用全员或本人所在部门的制度。
- 标题里带“示例”的制度存在时，页面底部提示“仅用于演示，正式使用前由管理员替换”。
- 详情弹窗可预览正文并下载原文（下载同样要登录且符合可见性规则）。
- **可见性规则只实现一次**：`store.isPolicyVisibleTo / listVisiblePolicies / findVisiblePolicy`。列表、详情、下载以及之后的智能问答都必须调用这一套，不能在各自页面里另写判断。

## 示例账号（测试用）

`示例账号/` 文件夹里有三个文件：

- `示例员工导入.csv`：可直接用“员工管理 → 批量导入”导入的示例员工——12 名普通员工（产品部 3、技术部 3、销售部 2、财务部 2、人力资源部 2）+ 1 名 HR 管理员 + 1 名产品运营，员工编号统一为 `ONB001`–`ONB014`；

- 这些示例数据全部为虚构，只用于本机演示测试；统一初始密码只写在这个文件里，页面文字里不出现。

## 模型配置（仅系统管理员）

左侧“管理后台 → 模型配置”只有系统管理员能看到。

- 左边“对话模型连接”：接口地址、模型名称、密钥（密码框）、回答随机度（0–1，步长 0.1）、单次回答最大长度（512–6000）。
- 保存后密钥用本机设备密钥做 AES-GCM 加密存放；再次打开页面时密钥框为空，只提示“已加密保存，留空保留现有凭据”，页面任何位置都不显示明文，也不会把密钥原文回传。
- “保存配置”：校验通过后配置版本号 +1，并在“操作审计”里记录 谁 / 什么时候 / 改了什么（**不记录密钥**）。
- “测试已保存连接”：真的调用一次 `{接口地址}/chat/completions`；成功显示“连接成功，用时 X 毫秒，消耗 X 个计算单位”，失败按 密钥无效 / 地址或模型名不存在 / 网络或跨域限制 等给中文提示。
- 右边说明卡片：配置版本、“回答之前一定先验证”、密钥存放方式；底部提示外部模型会收到员工的问题和相关制度片段；年假余额由系统直接读取，不交给模型计算。

> 演示版限制：当前是纯本机运行、没有服务端，无法做到真正的“服务端加密”——密钥是**用本机设备密钥加密后存在浏览器里**，页面不显示明文；接入后端后应改为服务端加密保管，页面也不会再接触密钥。

## 反馈跟进（服务管理）

- 员工点“没有帮助”后，这条差评会自动出现在“服务管理 → 反馈跟进”，默认状态“待处理”。
- 每条差评显示：原问题、原回答（当时的结论与引用）、当时引用的制度名称/版本/位置、员工填写的原因和补充说明、时间。
- HR 可以把状态改为 待处理 / 处理中 / 已处理，并填写处理说明；每次保存都会记录处理人、时间和说明。
- “加入评测集”：把这道差评问题保存成以后可以反复测试的题目，保存前必须勾选“已确认已去除敏感内容”；评测集本身在阶段 10 完成。
- **不会自动修改制度或任何设置**：页面明确提示改进必须由人确认，系统只记录反馈与处理过程。

## Agent 执行轨迹

员工左侧“Agent 执行轨迹”列出自己最近的问答；HR / 系统管理员可以看到所有人的轨迹（管理员多一列“员工”）。点开一条，按顺序展示这次回答经过的每个阶段：

1. 理解意图
2. 查找制度原文（列出找到的原文段落、来自哪份制度哪个版本）
3. 生成回答
4. 规则核验
5. 语义核验
6. 最终状态

每个阶段显示结果（通过 / 未通过 / 部分通过 / 未执行）、耗时和简要说明。查找阶段会检查当时的原文现在是否还一致：制度已下架标“制度已下架”，原文被改动标“当前切片已变化”，不会假装还是原样。旧回答没有记录阶段耗时时会标注“旧回答没有记录这个阶段”。

用途：出了问题时能定位是没找到制度原文、生成错了，还是被核验拦住。

## 知识缺口诊断（管理工作台）

自动汇总三类“缺口事项”：

- 回答状态为“依据不足”的咨询；
- 员工点了“没有帮助”的反馈；
- 被转人工的工单。

同一类问题按关键词相近归组，显示出现次数、最近一次时间、涉及的部门和来源标签。每个事项可以指派跟进人、标记状态（待处理 / 处理中 / 已补充知识 / 无需处理）并写处理说明；也可以“加入评测集”，保存前必须人工确认已去掉个人敏感信息。

说明：目前按关键词相近归组，**不是真正的语义聚类**，不同说法可能被分成不同组（页面上也有这句话）。

## 制度更新与签收

分 HR 后台与员工端两边：

- **HR 后台 → 制度更新与签收**（HR 管理员 / 系统管理员）：
  - 列出所有已发布制度，每份可以“发起签收”；
  - 发起前先显示与上一版本的差异对比（新增 / 删除 / 修改内容，行级对比）；
  - 选择签收范围（全员或某个部门）后确认发起；
  - 发起时把当时的制度正文完整保存为不可更改的快照，之后制度再更新也能证明员工当时确认的是哪个版本；
  - 签收活动列表显示应签收人数、已签收人数、完成比例，可展开查看未签收名单和已签收时间/版本。
- **员工 → 我的制度签收**：列出需要本人签收的制度，点开阅读完整正文（快照内容），点“我已阅读并确认”完成签收，记录签收时间和版本；也可查看已签收记录。
- 页面文字明确说明：签收只代表已知悉制度内容，不代表掌握程度或考试通过。
- 收件人以发起那一刻的名单为准，之后新入职员工不会自动加入该次签收。
- 消息与待办里也会出现“待签收：制度名”，点开直接阅读并签收。

## 开发者后台（检索调试 / 切片管理）

仅系统管理员可见（管理后台 → 开发者后台）。

### 检索调试

- 顶部显示：当前配置版本、在线使用的提示词版本、当前原文数量设置、评测题数量。
- 左侧检索参数：最终保留的原文数量（1–20）、意思相近候选数量、关键词命中候选数量；说明“意思相近与关键词命中两路候选合并后，最终只取前几段；部门权限过滤始终在排序之前”。
- 右侧输入问题，选择以哪个部门的员工身份测试，点击后列出原文片段：排名、制度名/版本、位置、原文内容；排名分数旁注明“仅用于排序，不是可信概率”。
- “保存草稿”只写入草稿，不会立刻影响员工；正式生效要走阶段 11 的发布流程（当前还没做发布）。

### 切片管理

- 选择一份制度，查看它被切成的片段：编号、位置、字数、内容。
- 每个片段保留来源信息：制度、版本、标题、页码（页码按每页 800 字估算）。
- 可以修改某一段内容（只改切片索引，来源信息保留）；也可以调整切分长度后“重新建立索引”。
- 重新建立是后台任务：显示进度条、任务状态和结果（共几段、切分长度），演示版在本机模拟后台进度。
- 页面提示：检查一下金额和它适用的条件有没有被切到两段里。

### 评测集 / 运行记录

- 评测集每题包含：名称、问题、以哪个部门身份提问、应该引用哪些制度、回答里应出现的关键词、是否应拒答（依据不足 / 越权）。
- 支持新增、编辑、删除；可以从“差评”“知识缺口”导入；阶段 6-6 的 43 题验收题库会作为内置种子自动导入（也可点“导入验收题库”）。
- 勾选若干题点“运行评测”，后台逐题运行；运行记录显示每题：应引用制度是否命中、关键词是否出现、拒答是否符合预期、得分；顶部显示整体通过比例。运行中的记录每 2 秒自动刷新。
- 每题允许人工复核：标记“通过”“不通过”并写理由（不通过必须写理由）。自动检查不能完全代表好坏。
- 页面说明：目前没有自动语义评分，也不做大规模压力测试。

### Prompt 管理

- 把让 AI 做事的系统指令做成可查看、可编辑的配置：理解意图、生成回答、核验回答，每项有名称、作用说明和当前内容。
  - 说明：理解意图目前是本地规则判定（不调用模型），页面上的文字用于记录判定口径；生成回答与核验回答的 Prompt 会在调用模型时使用。
- 每次保存都生成一个新的草稿版本，记录版本号、修改人、时间和修改原因；草稿不会立刻影响员工，正式生效要走阶段 11 的发布流程。
- A/B 对比：选择两个版本，在同一批评测题、同一份找到的原文条件下各跑一遍，并排显示两个回答、各自得分与检查结果。
- 对比前会检查条件：必须使用同一模型、同一批原文；如果未配置模型（两边都用本地摘要、Prompt 没实际参与）或两次条件不同，页面会明确标“不可直接比较”，不让人据此下结论。
- 页面说明：这是离线对比，不等于线上真实用户的随机实验。

### Prompt 发布

- 完整流程：保存草稿 → 查看与线上版本差异 → 运行回归 → 人工确认发布；有问题可以从历史版本恢复为新草稿再走一遍。
- 保存草稿不会影响员工，只有发布才会生效（发布后线上回答使用新版本的检索数量与提示词）。
- 草稿列表显示：基于哪个线上版本、保存时间、与线上版本的逐项差异（只列有变化的项并高亮）、回归结果摘要和失败原因。
- 每个未发布草稿可“运行回归”：使用草稿里的全部设置（检索数量、提示词）检索和回答；最多取评测集前 10 道有效题；每题用线上提示词（A）与草稿提示词（B）各回答一遍。同一时间只允许一个评测任务，已有任务会提示“请等待完成”。
- 发布前逐项检查，任何一项不满足都会拒绝并说明原因：
  - 回归必须针对这个草稿且已完成；
  - 回归开始后制度知识库不能变化（制度发布/下架/修改、切片变化）；
  - 回归开始后模型连接设置不能变化；
  - 草稿提示词下所有回归题必须全部通过（不是按百分比）；
  - 参与回归的评测题不能被修改或删除；
  - 草稿基于的线上版本必须仍是当前线上版本；
  - 草稿不能已经发布过。
- 发布需人工勾选确认并填写至少 5 个字的发布说明；发布后写入操作审计，说明里包含发布的版本。
- 回滚：选择历史版本“恢复为新草稿”，不会直接替换线上；恢复出的草稿仍需重新回归与确认。
- 页面说明：离线评测不能覆盖所有真实情况；回归只覆盖所选的那几道题；回滚也需要评测，不是一键切换。

## 运营分析（产品运营）

管理后台 → 运营分析（产品运营 / 系统管理员可见）：

- 顶部时间范围：近 7 天、近 30 天、近 90 天。
- 指标卡：咨询总数、已解决比例、转人工比例、工单平均首次响应时长、入职任务逾期数、制度签收完成率。
- 图表：咨询主题分布（按关键词归类为年假、报销、入职、请假、薪酬福利、其他）、未解决问题排行。
- 每个指标和图表都可以点击，查看构成这个数字的原始记录列表（会话、工单、任务、签收活动），数字与记录必须能对上。
- 口径说明（页面上也有小字）：主题是关键词分类；“未解决”是代理指标（依据不足、差评或转人工），不是满意度；入职任务逾期是当前快照；制度签收完成率是累计值；不要把指标说成满意度或节省的工时。

## 制度冲突检查（HR 后台）

- 当制度处于“待发布”时，系统把它与已发布、适用范围相同或重叠的制度逐段比较，找出疑似差异：金额不同、期限不同、审批条件不同；最多列 60 项候选。
- 每项候选并排显示新旧两段制度原文，带制度名称、版本和位置。
- 负责人逐项判断：**确实冲突，需要处理** 或 **不冲突，只是情境不同**，并写理由；全部确认后才允许发布。有未确认项时，发布按钮会显示“尚有 N 项未确认”。
- 如果之后制度正文发生变化，候选签名会变化，之前的确认自动失效，需要重新确认。
- 页面说明：这是候选差异检查，不是法律判断，也不是完整语义推理；可能漏检，也可能把不同情境误列为差异。

## 回答前自动核验（防止答错）

回答生成后会先经过核验，再决定展示哪些结论：

- **第一层：规则核对**——每条结论引用的原文必须在对应制度里逐字存在；结论里的数字、期限必须出现在引用原文中；找不到就判不通过。
- **第二层：独立 AI 核验**——配置了模型时，另发一次独立请求，让核验模型判断“这条结论是否被它引用的完整原文明确支持”，扩大解释、漏掉例外或条件都算不通过；未配置模型时这一项记“未执行”。
- **未通过核验的结论不展示**；全部不通过时回答“依据不足”并说明缺少什么。
- **冲突检测**：同一事项、同一单位、数字不同的制度要求会被判为真正冲突，回答会说明冲突、把双方原文并列展示、建议转人工确认，不替用户选一个；主题不同、详略不同、示例标注都不算冲突。
- 回答状态分为 **依据充分 / 部分有依据 / 依据不足 / 存在冲突** 四种，用不同颜色标识；回答下方有“查看验证过程”，列出每项检查名称、结果（通过/部分通过/未通过/未执行）和说明。

## 个人年假问答（员工服务助手）

员工问“我今年还剩多少年假？”这类问题时，回答直接来自年假账本（阶段 4），不经过模型：

- 先判断问题类型：只问制度 → 检索制度回答；只问本人年假 → 读账本；两者混合（如“年假余额多少，能结转吗”）→ 分别回答再合并；问本人部门/身份 → 读个人资料；问题太含糊 → 先请对方补充说明。
- 问别人的年假或个人信息（如“张三还有几天年假”）→ 明确拒绝：“只能查询你本人的信息”，不透露任何内容。
- 年假回答里有一张卡片：年度、剩余天数（大字）、截至时间；“最近余额变动”可展开，显示流水原因、增减天数和时间。
- **余额只来自年假账本（流水合计）**，不会交给模型估算或推算；卡片下方写明“余额由 HR 维护，直接读取年假账本，未经模型计算”。
- 如果账本流水里带“示例”二字，卡片上标“示例数据，非真实年假”。
- 年份默认当前年度；问题里写“去年 / 明年 / 2025 年”时才用对应年份，不会编造年份。
- 混合问题（余额 + 制度）会同时给出年假卡片和带引用的制度结论。

## 带引用的回答（员工服务助手）

员工在“员工服务助手”里提问后，系统会先检索（见上一节），再生成带引用的回答。

- **回答只依据检索到的原文**：没有配置模型时，用“本地摘要”兜底——直接从原文里摘句作为结论并标注模型名；配置了模型后，把原文片段和严格约束发给模型（只依据原文、每条结论单独引用、依据不足要说明缺少什么），并要求返回结构化 JSON。
- **结论 + 角标**：回答拆成若干条结论，每条后面标它引用的原文编号（上标数字）。
- **回答依据 · N 处引用**：可展开，每处引用显示制度名称、版本、位置、原文摘录和“下载原始文档”链接（下载仍走同一套可见性校验）。
- **依据不足 / 只能部分回答**：检索不到原文或原文没有覆盖关键条件时，明确显示“依据不足”或“只能部分回答”并说明缺少什么，不猜。
- **示例制度提示**：引用了标题带“示例”的制度时，回答下方用小字提示“当前引用示例制度，仅用于体验，不代表真实公司政策。”
- **异步与恢复**：回答在后台生成，页面显示“正在查询并核对依据，请稍候…”，成功后自动出现；切到别的页面再回来（或刷新）仍能看到最终结果，未完成的回答会自动继续。
- **失败可重试**：模型调用失败时显示中文失败原因（密钥无效、地址/模型名不对、跨域/网络、超时、返回格式不对等），并提供“重试”，不会一直转圈。
- **底部信息**：显示本次耗时和所用模型名称（本地兜底时显示“本地摘要（演示，未调用模型）”）。

## 制度检索与查找测试（仅管理员）

- 新增 `js/retrieval.js`：把制度正文切成可引用的原文段，每段带制度名、版本、适用范围、章节、段号、字符区间和原文。
- 检索顺序固定：**先**用 `store.listVisiblePolicies(user)` 按“已发布 + 在有效期内 + 全员或本人部门”过滤（与制度中心同一套规则），**再**在可见范围内打分排序，不会反过来。
- 打分同时考虑关键词命中（领域词 + 两字词重合）和意思相近（本地轻量语义相似度：字词向量余弦 + 同义词扩展），两者各占一半后合并排序，返回前 6 段。
- 制度发布、下架或调整适用范围后，下一次检索会立即按新的可见范围生效；`store.changePolicyScope(policyId, scope)` 提供适用范围调整入口，“查找测试”页底部另有一个验收辅助工具，可直接改某份制度的适用范围来验证结果变化。
- 管理后台新增“查找测试”页（HR 管理员 / 系统管理员可见）：输入问题即可看到命中原文、来源制度与版本、所在章节/段号、分数构成，用于验收检索；没有命中时提示“没有找到相关原文”。
- 本步骤只做查找、不生成回答：不会调用模型，员工端聊天仍是占位回复。

## 数据保存在哪里

所有数据（账号、密码摘要、登录状态）都只保存在**这台电脑的浏览器本地**，不会上传到任何服务器。

密码以“随机盐值 + SHA-256 摘要”的形式保存，页面上不保存明文。

## 忘记密码 / 想重新开始

- 登录页的“忘记密码？”只给出联系 HR 或系统管理员的提示（演示版没有真实的找回流程）；
- 演示时如果彻底登不进去，可以点登录页底部的“演示用：清空本机数据”，确认后回到“创建工作空间”；
- 也可以清除浏览器中本站的本地数据。

## 配置文件（放机密信息的地方）

`config/app-config.js`：专门放后续要用的模型服务地址、密钥等机密信息。页面文字和示例数据里都不会出现这些内容，目前保持为空。
